# 原生任务通道与活跃群检查 Implementation Plan

**Goal:** 任务作为 DS Bot 原生功能独立投递与渲染；五分钟检查仅面向已启用且当前正式任务未完成的群组。
**Architecture:** 以现有 SQLite 正式计划作为任务状态依据，专用 taskflow 来源、投递入口和 conversation 投影作为任务通道。定时检查独立于异常恢复 sweep，群任务启用状态持久化并在设置中提供真实开关。
**Tech Stack:** DS Bot Host/Client、DSH Session 及 conversation events 扩展、SQLite、React。

已确认用户规则：近期开始且仍未完成的当前任务，以及群组已启用，才参与检查；切换聊天页面不影响。当前未完成的正式计划持续视作活跃任务，不用最后消息超时将卡住任务排除。完成/取消/暂停或停用停止催办。

2. [x] 增加群任务启用字段与设置开关，经正式更新接口持久化。停用不修改原结果或删除计划，重新启用依据最新计划状态恢复检查。
