# 群聊审批卡与实际调用技能 Implementation Plan

> 主 Agent 负责实现、测试、候选打包和最终验收；子 Agent 仅只读分析/审查。

**Goal:** 用户直接在对应群聊拒绝/通过待审批操作；任务流看板显示 Bot 实际调用的技能，即使该技能未预分配。
**Architecture:** 使用公开 `conversation.input.dock` 在群聊天输入框上方渲染原审批组件，订阅现有 `work.approvals` 并复用一次性审批 RPC。保留现有真实调用事件观察器，在 group+bot 的调用记录上补全成员与任务投影，按任务时间范围关联，不用分配清单推断调用。
**Tech Stack:** DS Bot Cordis plugin、React、公开 DSH slots、现有 taskflow API、Node tests。

## 用户已确定的行为

- 群聊直接出现审批卡，显示请求 Bot、工具/操作、原因及实际详情，提供拒绝/通过；不要求打开设置或成员列表。
- 通过仅授权当前请求一次；拒绝、取消、失效、重复点击、请求执行失败不可当成通过。
- 仅显示当前群的待审批请求；不同群里同一 Bot 的请求不能混入。
- 技能栏以实际调用优先，未分配但实际调用的技能也显示；分配与实际调用分别标记。
- 保留模型、工具、五项折叠/展开和看板既定视觉骨架；主理普通回复与正式任务卡修复继续保留。
