# DS Bot 心得、技能文件与实际加载补全 Implementation Plan

**Goal:** 完成用户已授权的心得存储、技能晋升文件、群 Bot 确定性加载和共享库闭环。
**Architecture:** SQLite 保留审核、来源和权限事实；Markdown 文件是可重建的只读发布物。群技能注册到 Agent 自己的 DSH scope；宿主在正式 system-prompt/assemble 中注入合规技能正文并记录加载证据。跨群公开由独立人工审批控制。
**Tech Stack:** Node.js、SQLite、DSH Cordis SkillRegistry 与 system-prompt/assemble。

## 接受条件

- [x] 合并心得和逐卡来源生成项目数据目录内 Markdown；历史缺失来源显示缺失，不伪造。
- [x] 已双审技能导出为 groups/<room-key>/skills/<skill-name>/SKILL.md，附 tier、内容摘要和来源清单；草稿不发布（隔离回归，真实库当前无技能）。
- [x] 本群已审核技能通过会话级 Provider 可发现并可加载；每次正文读取重新验证成员、群、等级和审核状态（真实 SkillRegistry 隔离回归）。
- [ ] 每次群 Bot 的模型请求由宿主加载 taskflow 指引及相关已审核技能正文，记录 session、群、Bot、技能 ID、内容摘要和加载时间；失败不能假报加载成功。
- [x] 共享库有显式发布和撤回工具，发布审核绑定准确正文和来源；未发布技能不能跨群读取，发布后仍受读者等级控制（0.3.17 来源绑定与身份刷新修复、81 项隔离分片及独立复审闭环，已实装）。
- [x] 旧事件补齐唯一隐藏索引，来源从真实 note_saved 事件恢复；没有原文时保留缺口。
- [x] 三层晋升、双审、导出、同群及共享检索、真实 DSH SkillRegistry 和正式请求装配有隔离回归证据。
- [x] 更新插件与 app 版本、构建、门禁、独立审查、备份并实装；实际环境无法完成的验收逐项保留。

## 实施步骤

1. 扩展 test/knowledge.test.mjs：已审核文件导出、共享发布/撤回、跨群和等级负例；先观察预期失败。
2. 在 taskflow/knowledge.js 增加共享权限与查询；新建 taskflow/publication.js 管理文件发布及完整性。新增 taskflow_skill_publish/unpublish 工具，并同步 constants.js。
3. 添加正式 Agent scope 的技能 Provider 和模型请求装配模块，复用 taskflow/state.js 的身份解析；测试真实 SkillRegistry 的 scope 隔离、撤权后 get、内容确实进入最终 assembly。
4. Scheduler 补建旧事件索引；知识库存储逐卡原始来源和合并心得的文件发布物，测试多次启动幂等和缺失来源。
5. 运行变更相关测试与 build/lint 后检查全量失败的首因；不得把测试样例写入真实群技能库。
6. 独立审查所有新增入口和回归，修复真实问题；记录修订范围、实际已安装版本和验收边界。

## 默认行为

- 群技能默认仅同群共享；跨群发布需主理调用并由宿主请求一次人工批准，撤回立即影响后续读取及模型请求。
- 每次群模型请求始终装配 taskflow 操作指引，相关已审核技能按当前卡目标和 Bot 职责排序，最多加载三项正文；其余通过有权限的技能目录/检索按需读取。
- 不自动移动、删除用户现存文件，不覆盖已有人工技能；发布文件位于插件自己的数据目录。
- 不发送未经授权的真实群消息或调用计费模型来制造验收数据；真实调用缺授权时报告对应未完成项。
