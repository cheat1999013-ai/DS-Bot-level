# 原生任务流监控界面

## 目标

DS Bot 群聊的「任务流」页签采用用户参考图的信息层级：计划总览、紧凑的执行卡摘要、按时间倒序的事件时间线。保留原生群聊面板，面板调宽会收窄聊天列；设置页保持在面板之上。

## 数据与交互

当前任务流程展示规则以用户本次回归纠正为准（详见 `taskflow-executor-only-regression.md`）：主理人和当前群管理员只在概览展示，不出现在执行任务摘要、流程节点或执行轨道；同一群/计划/卡/执行者在流程区仅占一行，开始、派发、提交、验收、失败和真实重试保留在该行可展开的任务历史中。下文旧版“逐事件行、计划终态行”描述已被此规则取代；账本事件不删除，其他布局与能力保持。

- 从群聊打开时默认筛选当前群；可手动查看全部群组或其他群组。跨群筛选只改变只读视图，当前群面板不对其他群的计划提供确认控件；筛选本身不创建任务、会话或派工。
- 总览展示所选范围最新计划的主理 Bot 原生头像、模型、目标、计划状态、卡片 ID 和验收进度；总览中的派发卡保留执行 Bot 原生头像。任务摘要的正文只显示 Bot 名称，不在正文内重复头像；对应的左侧 Bot 轨道节点使用执行 Bot 原生头像。时间线事件中的 Bot 身份文字旁保留原生头像。派发卡、任务摘要与事件行用彩色标签展示真实 `卡片 ID · 计划 ID`（悬停可读完整 `计划 ID/卡片 ID`），以区分同一个 Bot 做过的不同任务；计划终态只显示计划 ID。卡片摘要还显示执行 Bot、状态、模型、已分配技能和当前群内工具；模型始终单独显示，工具和技能合计默认最多五项，其余收为 `+N`，可展开及收起。当前任务实际调用的技能按最近调用顺序提前，来自当前群成员的技能加载事件；没有调用记录时保持原分配顺序，进程重启前的调用不冒充已观测到的历史。总览内派发预览的正文位置显示当前计划已保存的合并心得（标题与正文），没有心得时显示「暂无心得」，不拿任务目标或结果冒充心得；任务目标仍在下方任务卡中查看。心得沿用原位置的截断样式，悬停可读完整内容。
- 下方时间线读取 DS Bot 原生 SQLite 的事件，显示真实开始、派发、提交、失败、重试、验收和计划终态，附所属群组、Bot 和时间；每五秒轮询一次。任务摘要与时间线按稳定 Bot ID 分配不同的左侧轨道：摘要节点是该 Bot 头像，事件节点是状态圆点；节点每条轨道横向错开，同一 Bot 的摘要与事件沿自己的虚线相连。各行正文统一从轨道右侧同一列开始；任务摘要保留头像节点到正文的短横线，时间线事件不绘制节点到正文的横线。轨道表达所属 Bot，真实依赖只由卡片的依赖字段表示；头像与事件状态圆点不可混用。没有事件时显示空状态，绝不合成工具调用次数、计划数量或事件。任务摘要与时间线之间不插入独立的「计划心得」正文卡；已有心得仍留在知识库，不因界面移除而删除。
- 较宽窗口使用参考图的横向信息密度；狭窄面板中标签、摘要和来源自动换行，保持可读性。任务流面板允许比普通详情页更宽，但至少为聊天列保留现有的最小宽度。

## 实现边界

- `src/host/taskflow/scheduler.js` 提供有上限的只读跨群事件投影，按实际时间倒序。
- `src/host/taskflow.js` 扩充认证过的 `taskflow-state` 数据，全部群组与当前群组共用同一只读入口。
- `src/client/taskflow-dashboard.js` 绘制总览、摘要与事件时间线；原生页签消费者 `details-drawer.js` 直接导入其 `TaskflowPage`，`src/client/index.js` 直接导入其 `DASHBOARD_CSS`。0.3.22清理了无逻辑的旧 `taskflow-page.js` 转发层，面板测试也直接验证 dashboard；重建后129个发布文件与已安装版本逐字节一致。`browser-pane.js` 只针对任务流页签扩大可调宽上限；`i18n.js` 补齐英文原文的中文译文。
- `client.js` 由源码构建产生。视觉方向以用户提供的截图为准；先给用户查看真实渲染，再按用户要求运行测试、lint 与打包验收。
