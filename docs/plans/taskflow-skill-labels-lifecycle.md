# 技能分类标签与五天评分清理

## 用户明确要求

主理 Bot 在心得晋升为技能时赋予大类及细分类标签，例如「设计」「设计-UI」「设计-网页」「设计-图像」「设计-电商图像」「代码」及相应细分类，供执行 Bot 精确检索。用户最新调整：普通、优良技能每五天按调用次数和提示词质量评分，满分 5 分；低于 3 分进入待遗忘，期间主理和执行 Bot 仍可调用；下一轮仍低于 3 分则淘汰删除。精品技能不参评，不会自动待遗忘或淘汰；豁免由技能自身 premium 等级判定，与调用 Bot 的等级无关。

## 当前源码依据

- knowledge.js 的 searchSkills 目前只搜索 title/text；availableSkills/openSkill 同时执行群归属、等级和双审校验。
- 晋升入口为 TaskflowService.skillConsolidate，由当前主理发起并请求人工审核；新标签应与待审正文一同展示、绑定审核，不能在等待后被替换。
- skill_loads 记录实际请求上下文装配，不证明模型正确应用；skillOpen 当前没有持久调用计数。
- Retention 与 taskflowSweep 已有宿主定时器，可在同一生命周期执行到期检查，另加持久评分轮次，避免依赖内存计时。
- 导出由 publication 所有权标记及内容摘要保护，不能删除用户人工文件或沿目录链接清理其他路径。

## 推荐实现

### 分类与查找

沿用技能 ID，给技能增加主理维护的分类标签；支持一个主类与多个细类，标签可扩展而非写死设计/代码枚举。细类有明确父类，检索「设计」可涵盖设计细类，检索「设计-UI」优先准确匹配该细类；标签过滤与文本搜索可组合。检索结果和 SKILL.md 元数据同时包含标签、分数、生命周期及评分时间。搜索、精确打开、自动装配均保持原群/等级/分享审批约束，待遗忘不降低可调用权限。

晋升时标签与正文一起经既有双审；后续改标签必须经过主理权限和相应审批绑定重验。历史未分类技能保持可访问，标记待分类，禁止凭空替旧技能编标签。

### 评分依据（用户已确认）

推荐总分 = 调用频次 0–2 分 + 提示词质量 0–3 分。

- 统计最近完整 120 小时；主动打开并成功返回正文记一次读取，同一任务/技能/调用事件去重，重试或读取失败不加分。自动装配次数单独展示，不冒充模型实际应用。
- 频次量表：0 次=0；1 次=0.5；2–3 次=1；4–6 次=1.5；7 次及以上=2。
- 主理按六个质量项各 0/0.5 分评审：适用场景、输入及前置条件、可执行步骤、输出及验收、错误预防、边界及注意事项。各项附对应正文依据或缺失说明，质量总分由宿主相加，不能只提交一个无依据总分。
- 质量审核绑定技能正文版本/摘要和统计窗口，期间正文或权限变化时拒绝过期评分。同一窗口最多一条生效评分。
- 没有取得有效质量评审时显示待评分，不用默认零分推进淘汰。

用户已选择频次 2 分＋质量 3 分。

### 状态机与时钟

普通、优良技能自启用开始积累完整 120 小时，再产生首轮评分；周期时间与状态持久化，重启不重置。宿主未运行期间不虚构漏掉的评分，不用一次重启连续补两轮低分触发淘汰；新的一轮低分必须来自实际的下一独立窗口及有效评审。精品不创建评分窗口、不通知评分、不接受旧窗口评分；自动文件清理也再次排除精品。

- 有效评分 >=3：正常；待遗忘技能恢复正常，连续低分计数归零。
- 首次有效评分 <3：待遗忘，继续允许搜索、精确打开和自动装配。
- 下一轮有效评分仍 <3：淘汰，从本群及已共享的所有新检索/打开/装配入口撤下，清理本插件生成且未被人工修改的发布文件。
- 淘汰保留来源关系、评分依据和审计墓碑，避免破坏既有上层技能的来源证明；这不再是可调用技能。不得级联删除其他有效技能、原始心得、用户人工技能或备份。
- 自动清理应可重试；已淘汰文件不得被 syncPublications 重新导出，进行中的新请求在准入刷新时再次检查。

用户最新要求覆盖旧范围：仅所有已批准且满周期的普通、优良技能参评，频次记零，质量高的冷门技能可以达到3分而保留；待遗忘者同样每轮参评，精品豁免。

## 预期验收

隔离时间测试在120小时边界前后、<3/恰好3、低→高/低→低、重启/离线/重试/重复评分、待遗忘可读、淘汰的搜索/open/provider/准入刷新和共享撤回、权限与正文在评审期间变化、人工文件保护、来源及上级技能不误删上进行。新增旧三天账本只迁移一次、旧待评失效、精品跨多轮仍可用、旧精品评分及清理重试被拒绝。真实账号不制造技能和调用数据；最终区分源码/单元/安装/真实评分记录。
