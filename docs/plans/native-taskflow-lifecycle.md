# DS Bot 原生任务流：主理、记忆与等级

用户决定：任务流属于 DS Bot 源码和群聊，不依赖额外挂载的 Hermes 插件。旧的 `taskflow.sqlite` 只作为迁移来源；新账本属于当前 DSH profile 的 `plugin-data/hermes-bot-taskflow/coordination.sqlite`，长期知识属于同目录 `knowledge.sqlite`。迁移应通过 SQLite 一致性备份完成，不删除旧文件；只读宿主不迁移、不写库。群与 Bot 的作用域均由宿主会话身份推导，模型不能自行指定跨群范围。

## 行为与可验收边界

- 群主整句 `@成员 你是…主管/主控/总控/负责人/总监/组长/统筹/lead` 才任命；问句和夹任务不算。任命与手动切换管理员应把未结束计划的 principal 原子迁移，零管理员时不得留下无人可验收的计划。任命后无 @ 的用户消息只交主理判断；任务卡执行者的自然语言步骤和终稿不扩散，只有账本提报通知主理。
- 调度器在群成员、派发、页面审批、领卡时重复校验身份；退群的执行卡停止并通知主理。开始执行只发无唤醒通知。失败、崩溃、超时、未启动以真实卡状态和有限次数重试；耗尽后终止受影响依赖，主理决定重派或取消。用户确认卡在执行前暂停，附言留在卡片评论，拒绝保持暂停。
- 任务派发、提交及后续处理通知属于“Bot 任务”，不是群主发言或执行者的普通聊天；宿主消息携带 `taskflowEvent` 并保持非用户来源。聊天中的任务卡独立显示任务身份、真实计划/卡片 ID、时间和通知正文；运行轮次内、排队唤醒、重载及历史回看均保持这一身份。旧外置插件曾经通过用户 RPC 写入的提报通知，只在完整固定格式、目标主理、计划/卡片、成功提报事件以及十秒内事件时间全部对应时做只读展示兼容；不改写真实会话文件，用户自行输入或未被账本证实的文字仍用原用户消息组件。
- 整个计划成功完成后才给执行 Bot 计级，按群、计划和 Bot 去重，同一执行 Bot 多张卡只计一次，主理不因管理身份获奖。普通阶段每计划 +0.1 级，优良及精品阶段每计划 +0.01 级；单卡验收、失败和取消不新增奖励。持久层保存整数百分级，显示两位小数；低于 16 级为普通，16 至低于 27 级为优良，27 级起为精品，41 级以上仍保持精品。历史奖励保留原值，不追溯降级，只读旧库不迁移。
- `node_marks` 只存唯一隐藏关键词与节点索引，派发、结果、验收、心得各节点仅一个关键词。正文和群消息不含关键词；搜索返回词，打开返回原文。归档后以原词打开的是明确标记原文已清理的摘要。
- 每张卡心得先存草稿。全部执行者都提交后主理去重合并并消费草稿。长期库保存心得、验收摘要、来源和技能候选。按群和主题以中文三字片段比较标题及正文；每来源每层仅计一次，满足十个独立未消费来源才生成普通、优良、精品草稿。每级草稿先经 Bot 审核和人工审核，再归纳正文；审核前不晋升、不装备。合并心得与真实来源导出到 `library/groups/<群键>/insights/<计划键>/`；已批准技能导出到对应群的 `skills/<技能名>/SKILL.md`。群技能 Provider 注册在 Agent scope，模型请求装配时由宿主加载 taskflow 指引及按任务相关性排序的最多三项已批准技能，持久记录实际装配摘要；目录发现、正文装配与模型是否正确应用分别验收。跨群共享由 `taskflow_skill_publish` 单独请求人工批准，审核绑定准确正文；`taskflow_skill_unpublish` 撤回后阻止后续跨群检索、精确读取和装配。共享技能同样校验读者本群等级，未公开技能不跨群暴露。旧事件仅按真实账本补建索引和恢复 note_saved 来源，无法恢复的来源明确标为缺失。
- 完成且已合并心得的计划从可信验收时刻起 72 小时才清理；旧记录首次新版扫描设安全起点。先完整归档及校验 → 删除内置看板卡 → 删除账本明细，任一步失败可重试。取消/未通过验收的计划及心得删除；进行中、待人决策、已验收但未合并的计划保留。群解散后下一次调度清理对应卡和明细。

## 验收层级

测试以项目盘隔离目录 + mock 模型进行。源代码、测试、npm 包、DSH 安装实例和真实群聊消息分别核实；安装目录空或启动失败时不得宣称已实机验收。旧系统真实数据只读盘点授权不包含删除；任何安装或迁移都不得直接指向用户正在运行的 DSH_HOME 进行测试。
