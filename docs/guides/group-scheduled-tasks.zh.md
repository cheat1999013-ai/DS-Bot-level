# 群组定时任务与技能放置

## 创建群组定时任务

前提：DSH 已开启 Automation tasks；群组已指定有效主理，并且至少有一位其他执行 Bot。

1. 打开群组的任务面板，点击“新建群组定时任务”；也可以从设置的定时任务页进入。
2. 选择群组与执行 Bot，填写任务名称和要做的事情。
3. 选择一次、每天、每周或按间隔重复，并设置时间。日历时间按创建时浏览器报告的本地时区保存。
4. 点击“创建群组任务”。保存的是定时配置，正式任务卡在实际到点触发时创建。

到点后，宿主根据已保存的配置创建正式计划和任务卡，以当时有效的群组主理派给执行 Bot。执行者提交结果后，结果卡返回当前主理，仍需走正常验收流程。无需在任务正文里写 `@Bot`。

定时任务列表显示下一次时间及最近一次实际触发结果。群组已有未结束计划时，本次不覆盖它，也不另起重复计划；列表会保留未派发的原因。成员离群、主理失效或投递不确定时也会保留相应状态。同一发生时点的重复投递不会再次派卡。

删除定时配置只停止未来触发，已经生成的计划、任务卡和结果记录继续保留。修改任务内容或执行者时，可以删除配置后重新创建。现有单 Bot 提醒以及已有普通定时提醒继续保留原来的行为。

## 手工技能放在哪里

当前 Desktop 已通过官方文件系统技能提供方配置了 D 盘手工技能目录：

```text
D:\Documents\deepseek-harness\area skill\skills\
└─ evidence-check\
   ├─ SKILL.md
   └─ references\
      └─ checklist.md
```

该目录由宿主级 `skill-filesystem` 条目启用，提供方名为 `ds-bot-manual-d`，配置 `includeDefaultRoots: false`、`customSkillDirs` 为上述目录。各 Agent 的 preset 技能提供方保持原样；未更改整个 DSH_HOME。重启后已只读核验实际 DSH 后端持有该 D 盘目录的监视句柄。当前目录为空，尚无真实手工技能正文加载记录。

`SKILL.md` 最少需要以下格式：

```markdown
---
name: evidence-check
description: Use when checking sources and preparing an evidence-backed report.
---

核对来源、发布日期和可验证的原始材料。
区分已确认结果与尚未确认的信息，输出来源链接。
```

文件系统提供方只扫描技能根目录的直属技能目录或直属 `<name>.md` 文件，不会递归发现任意分类深度的 `SKILL.md`。因此不要再包一层“分类/技能名”。

保存后，在配置页的 DSH 技能目录刷新，检查技能名称和实际来源是否出现；出现代表可被发现，不代表某个 Bot 已经加载或执行。可以明确要求 Bot“使用 evidence-check 技能核对这份资料”，并核对实际调用记录。若设置了 `disable-model-invocation: true`，该技能会从模型可调用目录排除。

只有相应档案提供方已经挂载时，`<DSH_HOME>/profiles/<当前档案>/skills` 才是额外加载目录。配置页会根据当前宿主显示共享目录与确实已挂载的档案目录。Hermes 的技能目录不会自动等同于 DSH 的技能目录。

任务流的 `library/` 是经过知识库发布与准入检查的输出目录，不是任意手工技能的自动导入目录。不要覆盖其自动发布文件或已有人工技能。

全局插件和全局 MCP 服务由当前 DSH 配置管理，不需要在每个 Bot 的配置里重复选择。隐藏重复展示不会删除已有连接、技能、插件或改变已有的秘密访问权限。
